1. Aim

To model and implement the 0/1 Knapsack Algorithm using Dynamic Programming to optimize the loading and transport of emergency supplies for a Disaster Relief Resource Allocation mission following a major earthquake, maximizing the total humanitarian utility value while ensuring that the relief truck's maximum payload capacity \(W\) is strictly not exceeded.

2. Problem Statement

A massive earthquake has struck a remote mountainous region, isolating communities and destroying vital local infrastructure. A humanitarian relief organization is preparing an emergency transport truck with a limited payload capacity of \(W\) kilograms, making it impossible to transport every available relief item. Each relief item is characterized by a specific gross weight and an associated utility value, where the utility value represents the importance of the item in saving lives, mitigating suffering, and meeting urgent field medical needs.

The objective is to determine the optimal set of relief items that maximizes the total utility value without exceeding the truck's payload capacity. Unlike bulk consumable resources, critical disaster assets (such as surgical trauma kits, generators, satellite transceivers, and water purification units) are indivisible and cannot be transported in partial fractions. Therefore, the 0/1 Knapsack model is used, where each item must either be included in the truck entirely (1) or excluded (0).

4. Introduction

The 0/1 Knapsack Problem is a classic combinatorial optimization problem in algorithmic science. In the 0/1 Knapsack scenario, each item is indivisible and must either be chosen in its entirety or left behind. A greedy approach sorting by value-to-weight ratio, while optimal for Fractional Knapsack, fails in 0/1 Knapsack because fractional parts cannot be loaded, frequently leaving awkward payload voids. An exhaustive brute-force search requires evaluating \(2^N\) subsets, making it computationally infeasible for large \(N\).

Dynamic Programming overcomes this combinatorial explosion by breaking the problem down into overlapping subproblems, storing results in a matrix to avoid redundant recalculation, and achieving a globally optimal solution in pseudo-polynomial time \(\Theta(N \cdot W)\). In this assignment, we apply this method to an earthquake disaster relief operation to maximize the life-saving impact of every kilogram transported.

5. Theory

The knapsack problem involves selecting a subset of items with given weights and values to maximize the total value without exceeding a specified capacity constraint.

Types of Knapsack Problems

Type Description Algorithm Used
Fractional Knapsack Items can be divided into arbitrary fractions Greedy Algorithm
0/1 Knapsack Items must be selected whole (1) or not at all (0) Dynamic Programming
Bounded Knapsack Items can be selected up to a specified bounded count Dynamic Programming
Unbounded Knapsack Items can be selected an unlimited number of times Dynamic Programming

0/1 Knapsack Problem Concept

This variant strictly forbids taking fractions of items. Dynamic Programming constructs an \((N+1) \times (W+1)\) table where row \(i\) corresponds to considering items \(1 \dots i\) and column \(w\) represents available capacity \(0 \dots W\).

Difference: Fractional vs. 0/1 Knapsack

Feature Fractional Knapsack 0/1 Knapsack
Algorithm Greedy Algorithm Dynamic Programming
Item Division Allowed (continuous) Not Allowed (discrete binary)
Optimal Strategy Sort by value/weight ratio Subproblem recurrence tabulation
Time Complexity \(\mathcal{O}(N \log N)\) \(\Theta(N \cdot W)\)
Capacity Utilization Always fills capacity 100% May leave small slack if indivisible items don't fit

5. Theory (Continued)

Mathematical Representation

Objective Function: Maximize \(Z = \sum_{i=1}^{N} (v_i \cdot x_i)\)
Subject to Constraint: \(\sum_{i=1}^{N} (w_i \cdot x_i) \le W\)
Variables: \(x_i \in \{0, 1\}\) for all \(i = 1, 2, \ldots, N\)

Dynamic Programming Recurrence Relation

\[ DP[i][w] = \begin{cases} 0 & \text{if } i = 0 \text{ or } w = 0 \\ DP[i-1][w] & \text{if } w_i > w \\ \max\Big( DP[i-1][w], \; DP[i-1][w - w_i] + v_i \Big) & \text{if } w_i \le w \end{cases} \]

Step-by-Step Backtracking Process

  1. Start at \(DP[5][50] = 240\). Compare with \(DP[4][50] = 230\). They differ, so Item E (25 kg) is selected. Remaining capacity: \(50 - 25 = 25\text{ kg}\).
  2. Move to \(DP[4][25] = 130\). Compare with \(DP[3][25] = 100\). They differ, so Item D (15 kg) is selected. Remaining capacity: \(25 - 15 = 10\text{ kg}\).
  3. Move to \(DP[3][10] = 60\). Compare with \(DP[2][10] = 60\). Equal, Item C was not selected.
  4. Move to \(DP[2][10] = 60\). Compare with \(DP[1][10] = 60\). Equal, Item B was not selected.
  5. Move to \(DP[1][10] = 60\). Compare with \(DP[0][10] = 0\). Differ, so Item A (10 kg) is selected. Remaining capacity: \(10 - 10 = 0\text{ kg}\).

Optimal DP Manifest: Items A, D, and E with total weight \(= 10 + 15 + 25 = 50\text{ kg}\) and maximum utility \(= 60 + 70 + 80 = \mathbf{240}\).
Comparison with Greedy: Greedy sorts by ratio (A: 6.0, B: 5.0, D: 4.67). It loads A (10 kg) and B (20 kg), then D (15 kg), reaching 45 kg and 230 utility. It cannot fit remaining items, attaining only \(\mathbf{230}\) (10 utility points lost!). DP achieves 240.

7. Java Program (Part 1: Data Model & 0/1 DP Algorithm)

The following Java program models each disaster relief item and implements the exact 0/1 Knapsack Dynamic Programming algorithm with backtracking:

DisasterReliefKnapsack.java - Part 1: Model & DP Solver 
import java.util.*;

// Model representation of an emergency relief supply item
class ReliefItem {
    int id;
    String name;
    String category;
    int weight;      // in kg
    int utility;     // humanitarian life-saving value
    boolean perishable;

    public ReliefItem(int id, String name, String category, int weight, int utility, boolean perishable) {
        this.id = id;
        this.name = name;
        this.category = category;
        this.weight = weight;
        this.utility = utility;
        this.perishable = perishable;
    }
}

public class DisasterReliefKnapsack {

    // 0/1 Knapsack using Dynamic Programming with Backtracking
    public static void knapsack01DP(ReliefItem[] items, int capacity) {
        int n = items.length;
        int[][] dp = new int[n + 1][capacity + 1];

        // 1. Build DP Table Bottom-Up
        for (int i = 1; i <= n; i++) {
            int wt = items[i - 1].weight;
            int val = items[i - 1].utility;

            for (int w = 0; w <= capacity; w++) {
                if (wt <= w) {
                    dp[i][w] = Math.max(dp[i - 1][w], dp[i - 1][w - wt] + val);
                } else {
                    dp[i][w] = dp[i - 1][w];
                }
            }
        }

        // 2. Backtracking to identify selected items
        List<ReliefItem> selected = new ArrayList<>();
        int w = capacity;
        for (int i = n; i > 0 && dp[i][w] > 0; i--) {
            if (dp[i][w] != dp[i - 1][w]) {
                selected.add(items[i - 1]);
                w -= items[i - 1].weight;
            }
        }
        Collections.reverse(selected);

        // Display results
        int totalWeight = capacity - w;
        int totalUtility = dp[n][capacity];

        System.out.println("\n===== DISASTER RELIEF RESOURCE ALLOCATION (0/1 KNAPSACK DP) =====");
        System.out.println("Maximum Truck Payload Capacity : " + capacity + " kg\n");
        System.out.printf("%-4s %-34s %-12s %-10s %-10s\n", "ID", "Relief Item", "Category", "Weight", "Utility");
        System.out.println("--------------------------------------------------------------------------");
        for (ReliefItem item : selected) {
            System.out.printf("#%-3d %-34s %-12s %2d kg     %-10d\n",
                    item.id, item.name, item.category, item.weight, item.utility);
        }
        System.out.println("--------------------------------------------------------------------------");
        System.out.println("Payload Used          : " + totalWeight + " kg");
        System.out.println("Remaining Capacity    : " + (capacity - totalWeight) + " kg");
        System.out.printf("Capacity Utilization  : %.1f%%\n", (double) totalWeight / capacity * 100.0);
        System.out.println("Total Utility Value   : " + totalUtility);
    }

9. Implementation Details

The 0/1 Knapsack Algorithm is implemented using Dynamic Programming via a bottom-up 2D matrix approach. Each disaster relief item is modeled with its unique ID, name, category, weight, and utility value. A 2D array dp[N+1][capacity+1] is allocated where dp[i][w] records the maximum utility achievable considering the first \(i\) items with a weight limit \(w\).

The algorithm iterates through all items and weights: if an item's weight exceeds the current capacity \(w\), it inherits the value from the row above (dp[i-1][w]); otherwise, it takes the maximum between excluding the item and including it. After filling the matrix, a backtracking loop traces from dp[N][capacity] back to identify exactly which relief supplies were selected.

10. Time Complexity Analysis

The computational time of the 0/1 Knapsack Dynamic Programming algorithm is broken down across three primary sequential phases:

  • Table Initialization: Allocating the \((N+1) \times (W+1)\) table requires initializing \(W+1\) entries in row 0 to 0: \(\mathcal{O}(W)\).
  • Nested Table Filling: The outer loop runs \(N\) times (for each item). The inner loop runs \(W+1\) times (for capacities \(0\) to \(W\)). Inside the loop, each state transition evaluates a constant number of comparisons and additions: \(\mathcal{O}(N \times W)\).
  • Backtracking Recovery: Tracing backwards through \(N\) rows to extract the selected items list takes: \(\mathcal{O}(N)\).
  • Overall Time Complexity: \(\mathbf{\Theta(N \cdot W)}\) (Pseudo-polynomial time).

11. Space Complexity Analysis

The memory utilization is characterized by the storage needed for subproblem state memoization:

  • DP Matrix Table: The 2D array requires \((N+1) \times (W+1)\) integer memory cells: \(\mathbf{\Theta(N \cdot W)}\).
  • Space-Optimized Alternative: If only the maximum value is required without backtracking, a single 1D array traversed in reverse from \(W\) down to \(w_i\) uses: \(\mathbf{\Theta(W)}\) auxiliary space.
  • Input Storage: Storing the \(N\) relief items in memory requires: \(\mathcal{O}(N)\).
  • Overall Auxiliary Space Complexity: \(\mathbf{\Theta(N \cdot W)}\) for 2D DP (or \(\Theta(W)\) for 1D DP).

13. Advantages

  • Guaranteed Mathematical Optimality: Consistently identifies the global maximum utility, unlike heuristics.
  • Handles Discrete Indivisible Assets: Eliminates fractional splits impossible for real-world supplies.
  • Complete Item Identification: Enables fast \(\mathcal{O}(N)\) backtracking to recover exact manifests.
  • Avoids Redundant Work: Solves each subproblem once, preventing exponential recursion explosions.
  • Adaptable to Constraints: Accommodates priority weighting, perishability, and multi-vehicle dispatch.

14. Limitations

  • Pseudo-Polynomial Complexity: Time complexity depends on capacity \(W\); inefficient if \(W\) is astronomical.
  • Requires Integer Weights: Fractional or floating-point weights require scaling or approximation.
  • Higher Memory Footprint: Requires \(\Theta(NW)\) memory for the 2D table during full backtracking.
  • Indivisibility Slack: May leave small unutilized payload slack when remaining items exceed capacity.
