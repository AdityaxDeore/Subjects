1. Assignment Overview

This assignment explores Dynamic Programming with a backward approach on a directed, weighted multistage graph. We apply this to optimize package delivery routing across a series of logistical stages (e.g., from warehouses to final destinations via intermediate transit hubs).

2. Aim

To model a transportation network as a directed multistage graph and successfully implement an efficient algorithm to find the optimal delivery route. The algorithm must support batch processing of routes and dynamically adjust to real-time constraints such as traffic conditions, weather delays, and road closures.

3. Problem Statement

A logistics company, SwiftCargo, specializes in delivering packages across multiple cities. To optimize its delivery process, the company divides the transportation network into multiple stages (warehouses, transit hubs, and final delivery points). Each package must follow the most cost-efficient or fastest route from the source to the destination while passing through these predefined stages.

4. Primary Objectives

  • To model the logistics network into N stages strictly, simulating an industry-standard transportation graph.
  • To apply the Dynamic Programming backward approach resolving every possible source simultaneously.
  • To scale execution performance targeting \(\Theta(V+E)\) constraints enabling calculation of over 10,000 cities efficiently.
  • To simulate real-time route adjustment constraints such as traffic multipliers and complete edge disconnections (road closures).

5. Introduction & Theory

A multistage graph is a directed, weighted graph in which the vertices are partitioned into \(k \ge 2\) disjoint sets or stages \(V_1, V_2, \ldots, V_k\). Edges strictly connect vertices from stage \(V_i\) to stage \(V_{i+1}\).

Backward Approach (Dynamic Programming)

In the backward approach, we compute the shortest path from each node to the sink node starting from the \(k-1\)-th stage backwards down to stage 1. The recurrence relation is:

\[ Cost(i, j) = \min_{l \in V_{i+1}, \langle j, l \rangle \in E} \{ c(j, l) + Cost(i+1, l) \} \]

Where \(Cost(i, j)\) is the minimum cost from vertex \(j\) in stage \(i\) to the sink.

Mapping Theory to SwiftCargo Constraints

  • 1. Multistage Graph Modeling: The logistics network is modeled such that warehouses (Stage 0) strictly supply transit Hubs A (Stage 1), which supply Hubs B (Stage 2), before reaching final Destinations (Stage 3). This strict partitioning defines a true directed multistage graph.
  • 2. Efficient Algorithm Selection: While Dijkstra's Algorithm finds the shortest path from a single source, the Dynamic Programming (Backward Approach) was selected because it is mathematically superior for multistage structures. It calculates the optimal path from every warehouse simultaneously in a single bottom-up sweep.
  • 3. Scalability for Large Datasets: By utilizing a tabular DP array, we avoid the path explosion problem. The time complexity is strictly \(\Theta(V + E)\), allowing the system to securely scale and resolve massive datasets (e.g., 10,000 cities and 80,000 routes) in roughly 150 milliseconds.
  • 4. Real-time Constraints & Batch Processing: Traffic conditions and weather delays are translated into multiplicative mathematical penalties applied dynamically to base edge weights. Road closures logically sever edges (setting cost to \(\infty\)). Because DP solves all possible sources simultaneously in one pass, a single function call acts as a highly efficient batch processor for all pending delivery requests from any starting warehouse.

6. Algorithm & Complexity Analysis

Formal Pseudocode (Backward Approach)

Algorithm MultistageGraphDP(G, k, n)
// G: Adjacency list of the multistage graph
// k: Total number of stages
// n: Total number of vertices
// cost[1..n]: Minimum cost to reach the sink
// next[1..n]: Next vertex on the optimal path

1. Initialize cost[sink] = 0
2. For j = n-1 down to 1 do
3.     min_cost = ∞
4.     For each vertex r adjacent to j do
5.         if G.weight(j, r) + cost[r] < min_cost then
6.             min_cost = G.weight(j, r) + cost[r]
7.             next[j] = r
8.     cost[j] = min_cost
9. End For

10. // To extract optimal path for any Source S:
11. curr = S
12. While curr != -1 do
13.     print curr
14.     curr = next[curr]

Time Complexity: \(\Theta(V + E)\)

The outer loop iterates backward through all vertices \((V)\) exactly once. For every vertex, the inner loop evaluates all of its outgoing edges. Therefore, every single edge \((E)\) in the entire graph is checked exactly once during the execution. Because the algorithm processes each vertex and each edge exactly once, the total time complexity is bounded by \(\Theta(V + E)\).

Space / Auxiliary Complexity: \(\Theta(V)\)

The dynamic programming approach utilizes two 1D arrays: cost[] to store the minimum cost from each node to the sink, and next[] to store the forward path pointers. Both arrays are of size \(V\). Thus, the auxiliary space used is exactly proportional to the number of vertices, resulting in an optimal \(\Theta(V)\) space complexity.

8. Java Implementation

The solution uses Java. It models the stages and uses dynamic programming to solve all routes simultaneously in a single pass.

import java.util.*;

/**
 * SwiftCargo - Optimal Delivery Routing over a Multistage Graph
 * Technique  : Dynamic Programming, BACKWARD approach.
 * Complexity : Theta(V + E) time, Theta(V) auxiliary space.
 */
public class SwiftCargo {
    static final int INF = Integer.MAX_VALUE / 4;

    static class Edge {
        int to, base;                
        double traffic, weather;     
        boolean open = true;         

        Edge(int to, int base) { this.to = to; this.base = base; }

        int cost() {
            if (!open) return INF;
            // Cost calculation applying penalty factors for traffic and weather
            return (int) Math.round(base * (1 + 0.50 * traffic + 0.30 * weather));
        }
    }

    final int n, stages;
    final int[] stageOf;
    final String[] code, city;
    final List<Edge>[] adj;
    final List<List<Integer>> byStage = new ArrayList<>();

    int[] cost, next;
    int routes = 0;

    @SuppressWarnings("unchecked")
    SwiftCargo(int n, int stages) {
        this.n = n; this.stages = stages;
        stageOf = new int[n]; code = new String[n]; city = new String[n];
        adj = new List[n];
        for (int i = 0; i < n; i++) adj[i] = new ArrayList<>();
        for (int s = 0; s < stages; s++) byStage.add(new ArrayList<>());
    }
    void addCity(int v, int stage, String cd, String nm) {
        stageOf[v] = stage; code[v] = cd; city[v] = nm;
        byStage.get(stage).add(v);
    }

    void addRoute(int u, int v, int base) {
        if (stageOf[v] != stageOf[u] + 1) throw new IllegalArgumentException();
        adj[u].add(new Edge(v, base)); routes++;
    }

    Edge find(int u, int v) {
        for (Edge e : adj[u]) if (e.to == v) return e;
        return null;
    }

    // Real-Time Modifiers
    void setLiveConditions(int u, int v, double traffic, double weather) {
        Edge e = find(u, v);
        if (e != null) { e.traffic = traffic; e.weather = weather; }
    }

    void closeRoute(int u, int v) {
        Edge e = find(u, v);
        if (e != null) e.open = false;
    }

    // Dynamic Programming Algorithm
    void solve() {
        cost = new int[n]; next = new int[n];
        Arrays.fill(cost, INF); Arrays.fill(next, -1);
        
        for (int t : byStage.get(stages - 1)) cost[t] = 0;      
        
        // Iterating backward from the second-to-last stage
        for (int s = stages - 2; s >= 0; s--)                   
            for (int u : byStage.get(s))
                for (Edge e : adj[u]) {
                    int w = e.cost();
                    if (w >= INF || cost[e.to] >= INF) continue;
                    
                    // Relax the edge
                    if (w + cost[e.to] < cost[u]) {
                        cost[u] = w + cost[e.to]; 
                        next[u] = e.to;
                    }
                }
    }

    List<Integer> route(int src) {
        List<Integer> p = new ArrayList<>();
        if (cost[src] >= INF) return p;
        for (int v = src; v != -1; v = next[v]) p.add(v);
        return p;
    }

    String routeText(int src) {
        List<Integer> p = route(src);
        if (p.isEmpty()) return "UNREACHABLE";
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < p.size(); i++) {
            sb.append(code[p.get(i)]);
            if (i < p.size() - 1) sb.append(" -> ");
        }
        return sb.toString();
    }
}

10. Output Explanation

1. Initial Optimal Routes:
Initially, the algorithm finds the absolute shortest path via Dynamic Programming. For Warehouse 1 (WH1), the shortest path is WH1 -> HA1 (100) -> HB1 (200) -> DEST (300) = 600.

2. Real-time Constraints (Traffic & Weather):
We injected a heavy traffic delay (0.8 factor) on edge HA2 -> HB1 and bad weather (0.9 factor) on HB1 -> DEST.
Due to the weather penalty on HB1 -> DEST, its cost increased from 300 to 300 * (1 + 0.3*0.9) = 381. The DP algorithm instantly recognized that routing through HB1 is no longer optimal. WH1 successfully rerouted through HB2 resulting in a cost of 630, which is the new lowest possible cost.

3. Road Closures:
A complete blockage was declared between HB2 and DEST. Since HB2 is completely cut off, all shipments were forced to route through HB1 despite the severe weather penalty, causing the minimum cost to spike up to 681 for WH1 and 753 for WH2, but successfully ensuring delivery.

4. Scalability Validation:
A synthetic graph consisting of 10,000 cities and 80,000 routes was generated on the fly. The algorithm solved the routing for all 10,000 starting cities simultaneously in just 152 milliseconds, proving that the \(O(V+E)\) DP solution is exceptionally suited for massive industrial-scale datasets.
