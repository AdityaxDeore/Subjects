1. Problem Statement & Objectives

Autonomous University Examination Timetable & Multi-Room Allocation using Constraint Satisfaction Problem (CSP)

Given 14 departmental course examinations spanning multiple student cohorts, an inventory of 10 physical classrooms (each with a capacity of 30 seats), and 4 operational exam time slots distributed across Monday and Tuesday, the objective is to formulate and solve a timetable scheduling problem such that all hard constraints — zero student clashes, room exclusivity, and a combined seating capacity of at least 60 seats per course — are strictly satisfied.

  • Inputs: 14 course exams (FE, SY Comp Track A, SY IT Track B, TY, FY electives), 10 classrooms, and 4 time windows.
  • Output: A clash-free timetable allocating exactly two disjoint rooms to each course per slot, with zero cohort overlaps.
  • Dataset Used: generated_timetable.csv — stores course records, student enrollments, exam days, and room assignments.
  • Search Strategy: Recursive Backtracking Search with MRV variable selection, Degree Heuristic, LCV value ordering, and Forward Checking constraint propagation.

2. Theory & CSP Mathematical Formulation

In Artificial Intelligence, a Constraint Satisfaction Problem (CSP) models states as a collection of variables taking values from discrete domains, governed by explicit relational constraints. This factored representation allows universal, domain-independent heuristics to eliminate combinatorial thrashing without requiring problem-specific knowledge.

\[ \text{CSP} = \langle X,\; D,\; C \rangle \]
  • Variables \((X)\): A finite set \(X = \{S_1, S_2, \dots, S_{14}\}\), where each variable represents a course examination that must be scheduled.
  • Domains \((D)\): Candidate value sets \(D = \{D(S_1), \dots, D(S_{14})\}\). Each domain element is a tuple \((t,\,(r_a, r_b))\), where \(t \in \{\text{Mon\_09}, \text{Mon\_13}, \text{Tue\_09}, \text{Tue\_13}\}\) and \((r_a, r_b)\) are distinct classrooms with combined capacity \(\ge 60\).
  • Constraints \((C)\): Relational pairs \(\langle \text{scope},\, \text{relation} \rangle\) specifying legal assignments across variables.

3. Constraint Taxonomy & Search Heuristics

3.1 Constraint Taxonomy & Mathematical Relations

Scheduling correctness is maintained by enforcing hard operational safety rules alongside a soft institutional compactness objective. The four constraint categories below govern the complete solution space:

Constraint Category Formal Mathematical Relation Operational Meaning
Student Clash (Hard) \(\forall (S_i, S_j) \in E_{\text{conflict}} \implies \text{slot}(S_i) \neq \text{slot}(S_j)\) Courses sharing enrolled student cohorts cannot share a time slot.
Room Exclusivity (Hard) \(\text{slot}(S_i) = \text{slot}(S_j) \implies \text{rooms}(S_i) \cap \text{rooms}(S_j) = \emptyset\) A classroom cannot host multiple examinations concurrently.
Capacity Limit (Hard) \(\sum_{r \in \text{rooms}(S_i)} \text{cap}(r) \ge \text{students}(S_i) = 60\) Every course is allocated a room pair seating at least 60 students.
Temporal Bound (Soft) \(\min |\mathcal{T}_{\text{used}}| \quad \text{s.t.} \quad |\mathcal{T}| \le 4\) All 14 examinations are compacted into 4 slots across two days.

3.2 Heuristic Optimization & Pruning Principles

Without heuristics, naive backtracking must evaluate \(180^{14} \approx 3.8 \times 10^{31}\) candidate states. The four synergistic mechanisms described below eliminate thrashing and reduce the search to a tractable, deterministic path.

(1) Minimum Remaining Values (MRV) — Variable Selection.  Selects the unassigned variable with the fewest legal values remaining in its domain: \(\arg\min_{S_i} |D(S_i)|\). This fail-first heuristic detects inevitable dead-ends at the shallowest level of the search tree, preventing deep subtree thrashing before it begins.

(2) Degree Heuristic — Constraint Tie-Breaker.  When multiple variables share the same minimum remaining value count, the variable with the highest degree in the constraint conflict graph is selected next: \(\arg\max_{S_i} \sum_{S_j \in \text{unassigned}} \mathbf{1}_{[(S_i, S_j) \in E_{\text{conflict}}]}\). This maximises the impact of each assignment on reducing future search space.

(3) Least Constraining Value (LCV) — Domain Ordering.  Domain values are ordered by how few choices they eliminate for neighbouring unassigned variables, preserving maximal flexibility for future assignments and significantly reducing backtracking frequency.

(4) Forward Checking — Constraint Propagation.  Whenever variable \(S_i\) is assigned value \(v\), forward checking immediately filters conflicting values from all unassigned neighbours. If any neighbour's domain collapses to empty \((D(S_j) = \emptyset)\), the search backtracks at once, pruning entire subtrees before they are explored.

6. Concepts & Engineering Principles Used

1. Factored State Space Representation

Unlike uninformed search strategies such as BFS or DFS, which treat states as opaque objects requiring custom heuristics, CSP represents problem states as structured variable-value maps. This factored representation allows universal heuristics (MRV, Degree, LCV) to operate independently of problem-specific domain knowledge.

2. Fail-First Variable Selection Principle

By selecting the variable with the smallest remaining domain, any inevitable dead-end is encountered immediately at the top of the search tree. This principle eliminates the wasteful exploration of millions of subtrees that are structurally doomed to fail regardless of the values chosen within them.

3. Dynamic Forward Checking

Forward checking bridges the gap between static backtracking and full arc-consistency (AC-3). Each assignment proactively filters conflicting values from all unassigned neighbouring variables. If any neighbour's domain collapses to the empty set, the search backtracks immediately, pruning entire branches before they are explored.

4. Decoupled Architecture & Independent Verification

Following standard software engineering principles, the implementation strictly isolates data models (Subject, Room, ExamSlot), search logic (SmartExamCSPSolver), and output verification (TimetableValidator). The validator operates blindly on the solver's output, ensuring unbiased correctness checking.
