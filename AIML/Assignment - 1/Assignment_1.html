1. Problem Statement

Fatigue-Aware Tourist Route Planning using Real Road Network and Landmark Data

Given a real road network and the locations of real scenic landmarks, determine the optimal walking/cycling route between a source and a destination such that the tourist never runs out of stamina — using A* search, where the state includes both location and remaining stamina, and inserting a rest stop only when necessary.

  • Inputs: Source location, destination location, real road network (OpenStreetMap), tourist landmark dataset, tourist stamina limit.
  • Output: Optimal scenic route, total distance, number of rest stops, nodes expanded, route visualization on a real map.
  • Datasets used:
    • Road Network — OpenStreetMap, accessed live via the osmnx Python library
    • Tourist Landmarks — Custom CSV dataset of real famous landmarks in Pune

2. Theory & A* Search Modeling

3.1 Informed Search

Unlike uninformed search algorithms (e.g., BFS, DFS, Dijkstra's algorithm) which explore the search space blindly based only on path cost so far, informed search algorithms use additional domain knowledge — a heuristic function \( h(n) \) — to estimate how close a given state is to the goal. This allows the algorithm to prioritize exploring the most promising paths first, reducing the number of nodes expanded while still finding an optimal solution.

3.2 A* Search Algorithm

A* is one of the most widely used informed search algorithms. It evaluates each node using:

\[ f(n) = g(n) + h(n) \]

Where:
\( g(n) \) = actual cost from the start node to node n (here, real road distance in km)
\( h(n) \) = heuristic estimate of the cost from n to the goal
\( f(n) \) = estimated total cost of the cheapest path through n

3.3 Heuristic Used: Haversine Distance

Since our nodes are real GPS coordinates (latitude, longitude) on the Earth's curved surface, the straight-line (Euclidean) distance formula does not apply directly. Instead, the haversine formula is used to compute the great-circle distance between two points on a sphere. This distance is always less than or equal to the actual road distance (since roads cannot be shorter than a straight line), which makes it an admissible heuristic, preserving A*'s optimality guarantee.

3.2 Tourist Route Optimization Formulation

Standard A* is insufficient for a human traveler because reaching a node with zero stamina renders the path invalid. We expand the state space to include stamina levels:

  • State: Represented as a tuple \( (node, stamina\_level) \). Visiting the same node with different stamina levels constitutes two separate states.
  • Transition Cost: Edge length in kilometers. Stamina depletes proportionally to the distance traveled.
  • Constraints: If \( stamina\_level < 3 \text{ km} \) (Safety Margin) and the current node maps to a beautiful tourist landmark or cafe, the stamina is fully replenished (resting), but a "rest stop" penalty is recorded. If \( stamina\_level < 0 \), the path is pruned due to exhaustion.

4. Concepts Used

Extended State Space (Location + Resource): Classical A* treats a state as just a node. Here, the state was extended to (node, stamina remaining), since the same intersection reached with different stamina levels represents a different search state. This pattern is common in real constrained pathfinding problems.

Resource-Constrained Search / Conditional Resting: The algorithm only inserts a landmark rest stop when stamina would otherwise fall below a safety threshold and a landmark is available there — not by default. This reflects realistic decision-making rather than a blind "must-visit" search.

Working with Live/Real Geospatial Data: The road network was fetched live from OpenStreetMap using osmnx (via the Overpass API), instead of using a static hardcoded graph.

Data Cleaning of Real-World Datasets: Real datasets have inconsistencies (misspelled columns, missing values), requiring cleaning with pandas.to_numeric(errors='coerce') and dropna() before use — a step rarely needed with textbook data.

Handling MultiGraph Edges: Real roads can have multiple parallel edges between two intersections (service roads, flyovers), requiring G.get_edge_data() to correctly pick the shortest edge instead of assuming a single edge key.

Admissible Heuristic on Real Coordinates (Haversine): Instead of a manually assigned heuristic table, the heuristic here is computed mathematically from real lat/long values using the haversine formula, generalizing to any two points on Earth.

By extending the state to include stamina level, the algorithm found routes that are not just distance-optimal but actually feasible for a fatigue-limited tourist — inserting a sightseeing rest stop only when genuinely required.
